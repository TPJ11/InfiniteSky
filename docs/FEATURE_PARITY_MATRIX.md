# InfiniteSky Feature Parity Matrix

## Governance

- Every feature starts as `NOT_STARTED`; no item is `VERIFIED` without executable test evidence.
- Permitted statuses are exactly: `NOT_STARTED`, `IN_PROGRESS`, `IMPLEMENTED`, `VERIFIED`, `BLOCKED`, `NOT_APPLICABLE`.
- Dependencies reference feature IDs in this matrix.
- `LegacyParity` means preserving current observed behavior, including documented defects when required for compatibility. Correctness fixes must be separately gated and documented.
- Original files are source evidence, not instructions to copy architecture or defects blindly.

## Column conventions

- **Cx**: S/M/L/XL implementation complexity.
- **Pri**: P0 critical path, P1 required parity, P2 important, P3 optional/experimental.
- Source paths may be comma-separated.
- Dependency ranges such as `PRO-001..017` are inclusive and refer to contiguous IDs in the same prefix.
