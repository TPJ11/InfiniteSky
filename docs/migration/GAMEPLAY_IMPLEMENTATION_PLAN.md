# Gameplay Implementation Plan

## Scope and evidence policy

This plan covers gameplay features `GP-001..038` from [FEATURE_PARITY_MATRIX.md](../FEATURE_PARITY_MATRIX.md). The root Node.js runtime is authoritative: `package.json` starts `main.js`, which loads root `login.js`, `zone.js`, and `world.js` through VMScript. `FruitSalad/main.js` starts a separate RPC process tree configured by `FruitSalad/Config/processes.json`; its handlers are alternate/experimental evidence, not automatically interchangeable root behavior.

The original repository contains several active but incomplete handlers. An opcode registration or domain model does not establish feature completeness. The root `data` tree has zone spawn files, packet captures, and translation CSVs, but no `data/infos/005_00001.IMG`, item, skill, or monster information image used by `GameInfoLoader`. Source-derived algorithm tests therefore do not establish original-data parity.

Migration status means C# status, not original completeness. Only the isolated XP arithmetic and stat-allocation slices are currently `IN_PROGRESS`; no gameplay feature is `VERIFIED`.

## Ordered work and exit criteria

1. **Data and protocol prerequisites:** map the externally expected `005_*.IMG` records and complete action/item/world packet structures; add sanitized fixtures. Until then, source declarations alone are not game-data parity.
2. **Progression/stat foundations (`GP-004..006`):** complete the data catalog, integrate `LegacyExperienceAwarder`, add 0x2F/0x2E output and source stat recalculation with persistence; establish exact game-data vectors.
3. **Movement and player state (`GP-007..008`):** implement source-layout action decoding and legacy client-coordinate replication using Prompt 15 spatial state. Keep any corrected validation profile separate.
4. **Items and equipment (`GP-017..020`):** implement focused item actions with state conservation and targeted persistence before commerce, drops or trade.
5. **NPC/monster actors (`GP-012`, `GP-023`, `GP-026`):** wire spawn data and source state packets; do not invent AI or respawn behavior.
6. **Combat, skills, buffs and loot (`GP-009..016`, `GP-022`):** migrate only behaviors with complete formulas/data/packet evidence, separating legacy defects from corrected profiles.
7. **Social, commerce, events and return behavior (`GP-021`, `GP-027..038`):** implement each independently with disconnect and transactional tests.
8. **Quests (`GP-025`):** remain blocked until root client packet meanings and complete quest data/transition evidence exist. Do not copy the separate FruitSalad process implementation into root.

For each feature, tests must cover source-derived boundaries plus protocol and persistence effects where those effects are part of the original path. No code in this stage adds a scripting/plugin runtime (Prompt 17), administration (Prompt 18), or other later-stage system.
