# Administration and Command Compatibility Matrix

## Status and scope

Statuses describe the .NET migration, not whether Node.js source exists. `BLOCKED` means the feature is present in the legacy source but the .NET host has no safe execution path or required service boundary yet. No command in this matrix is `IMPLEMENTED` or `VERIFIED`.

The root `main.js` runtime is authoritative for the main server. `FruitSalad/` is inventoried separately because it is a distinct, experimental multi-process runtime; its commands are not aliases for root commands.

## Root game-chat dispatch contract

| Property | Source-backed behavior |
|---|---|
| Registration | On `world_started`, `main.js` calls `GMCommands.Start()`. That starts a VMScript over the direct files in `commands/`; each active module calls `GMCommands.AddCommand`. Directory enumeration is not sorted. |
| Replacement and aliases | `AddCommand` removes a same-name entry and appends the new command. `Alias(name)` creates another command record sharing the original level and callback. No unregister API exists. |
| Invocation channels | The root normal-chat `0x13`, faction-chat `0x3E`, and whisper `0x09` handlers each recognize a message whose first character is `/`, remove that character, call `GMCommands.Execute`, and return instead of relaying it as chat. This happens before the regular chat/faction/whisper behavior. |
| Parsing | Empty input is ignored. The command name is the substring before the first literal space (or all input if there is no space), lowercased; the rest after that one space is passed unchanged. There is no quoting, tokenization, or trimming. |
| Authorization | Each command has a numeric minimum `Level`; dispatch compares it against `client.account.Level`. `Character.IsGM` is a separate legacy field and is not the dispatcher’s authorization source. The root dispatcher does not define named roles. |
| Responses and failures | Unknown names send `Invalid Command`; insufficient level sends `account.Level too low for this command`. Callback exceptions are dumped to server logs; accounts at level 80+ also receive `ex.toString()`. There is no durable command audit record. |
| Output | `sendInfoMessage` sends the legacy system-message packet. Command callbacks can also write raw packets or mutate world, character, and database state directly. |

Source: [main.js](../../main.js#L35-L42) and [main.js](../../main.js#L163-L165), [GMCommand.js](../../GMCommand.js#L1-L79), [vmscript.js](../../vmscript/vmscript.js#L277-L360), [chat.js](../../packets/world/chat.js#L66-L117), [world.js](../../world.js#L575-L583), [account.js](../../db/account.js#L12-L20), [character.js](../../db/character.js#L48-L63).

## Root local console and operational commands

The root `cli.js` starts a local Node REPL during application startup. Its `/<word> [input]` dispatch is separate from game chat and does not use GM account levels. The REPL also accepts arbitrary JavaScript and `#` shell execution. CLI command names are case-sensitive in the property lookup.

## Disabled, absent, and unverified capabilities

- `commands/game_gmcommands.js` actively registers only `return`, without an execute function. Its `pvpkill`, `qreset`, `qclear`, `stat`, `patexp*`, stat setters, item/quest/monster operations, `kick`, `forbid`, `unforbid`, movement, and other listed names are comments, not commands.
- No active root mute, ban, suspension, warning, moderation log, or remote-administration endpoint was identified. Login ban checks and IP-ban checks in `db/account.js` and `packets/login/handleLogin.js` are comments.
- `announce` is not a root registered command. Root broadcasts are `b` and `n`; `y` is a zone-height query.
- There is no root command for a supported graceful restart. `shutdown` only sends a message.
- No C# command parser, registry, dispatcher, authorization service, audit sink, operator CLI, or migrated command handler exists.
