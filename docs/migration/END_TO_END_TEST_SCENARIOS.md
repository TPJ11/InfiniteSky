# End-to-End Test Scenarios

Statuses describe the exact executed scope. `VERIFIED` is limited to the named test behavior; it does not imply full-client, production MongoDB, or whole-server compatibility. Full matrix statuses remain in [`FEATURE_PARITY_MATRIX.md`](../FEATURE_PARITY_MATRIX.md).

| Scenario ID | Scenario | Preconditions and fixtures | Execution and expected result | Actual result, test implementation, and evidence | Status | Remaining blocker |
|---|---|---|---|---|---|---|
| `E2E-01` | Cold host startup | .NET 10; default test configuration; no DB/network | Build and start Generic Host; host enters running lifecycle, then stops cleanly. | `FoundationHostTests.HostStartsWithReadyFoundationAndStopsCleanly` passes. World is actually degraded because no zones are configured. This is a host lifecycle test, not a process/deployment smoke test. | `VERIFIED` | A supported game-ready configuration and direct process/deployment validation are not established. |
| `E2E-02` | Startup configuration/dependency failure | Invalid tick setting, then Mongo URI to closed loopback port | Host must fail visibly rather than report healthy readiness. | `FoundationHostTests.HostBuildThrowsForInvalidFoundationConfiguration` and `UnreachableMongoDatabaseFailsStartupAndIsNotReportedHealthy` pass; no database URL is exposed in the failure assertion. | `VERIFIED` | Live Mongo authentication/index compatibility is untested. |
| `E2E-03` | Login success through composed host | Host listeners enabled on free loopback ports; test account repository | Send source-layout login frame; receive legacy success response; create one account session. | `NetworkAuthenticationHostIntegrationTests.HostRoutesSocketLoginThroughAuthenticationAndCleansUpOnShutdown` passes using real TCP, host DI, framing, packet sink, authentication and session store. Persistence is substituted. | `VERIFIED` | Replace test repository with isolated MongoDB only when opt-in infrastructure is available. |
| `E2E-04` | Login failure responses | Real listener/sink/auth path; test repository | Incorrect password returns the source status and does not create a session. | `AuthenticationTests.LoginPacketUsesLegacyResponseAndCleansSessionOnDisconnect` exercises a real loopback listener and verifies the incorrect-password response. | `VERIFIED` | Production repository and live account documents are not involved. |
| `E2E-05` | Character list/selection | Authenticated account and representative character BSON/captures | Retrieve only owned characters and select a valid character without partial registration. | Not executed over the network. `PlayerActivationService` tests cover internal ownership/activation behavior, not client packets. | `BLOCKED` | Character-list/selection packet handlers, full Character wire codec, and server-side session-to-world binding are absent. |
| `E2E-06` | World entry | Selected owned character, ready world and canonical transfer frame | Resolve world/zone, spawn player, register entity, send established client notifications. | No client world-entry flow exists; no success response was fabricated. | `BLOCKED` | World handshake/transfer dispatch, packet evidence, and client-reachable player activation. |
| `E2E-07` | Zone entry and transfer | Valid zone configuration and source-backed transfer conditions | Enter/transfer with correct zone membership and rollback on failure. | Zone manager startup/stop and internal readiness are covered by `FoundationHostTests.ConfiguredZonesStartBeforeWorldAndSupplyRealReadiness`; no client enters a zone. | `BLOCKED` | World packet dispatch and transfer coordinator are absent; `.WREGION` evidence is unavailable. |
| `E2E-08` | Player visibility | Two active players and source-compatible visibility updates | Notify only clients that should see entity entry/exit. | Not executed; spatial candidate infrastructure tests are not a client visibility transcript. | `NOT_STARTED` | Player entity replication and world response packets are absent. |
| `E2E-09` | Movement | Active world player and proven movement request layout | Update position/index and emit source-compatible movement notifications. | Not executed over a network; no world movement handler is registered. | `NOT_STARTED` | Packet layout, movement policy, active world player, and output path are incomplete. |
| `E2E-10` | Gameplay operations | Original data and source-derived request fixtures | Verify an implemented gameplay request changes state, persists supported fields, and returns compatible bytes. | Not executed. Pure XP/stat arithmetic tests do not establish an integrated gameplay operation. | `BLOCKED` | Data catalogs, gameplay packet handlers, entity runtime and persistence coordination. |
| `E2E-11` | Script/plugin execution | A source-supported migrated script and lifecycle contract | Load, dispatch, handle failures, and clean up script effects. | Not executed; no compatible script runtime/API or event bridge is registered. | `BLOCKED` | Root shared-VM/API and FruitSalad runtime semantics remain unmigrated. |
| `E2E-12` | GM command authorization | Authenticated active character and source command | Reject unauthorized invocation; authorize, execute, and return source-compatible response. | Not executed; account `Level` is in the authenticated session but no chat handler or command dispatcher exists. | `BLOCKED` | World chat ingress/response, character ownership context and command services. |
| `E2E-13` | Client logout | Established login/world session and source-supported logout message | Save supported state and remove world/session/connection state. | No logout packet path was identified or executed. Disconnect cleanup is covered separately. | `NOT_STARTED` | Source-compatible logout/world transfer semantics and client-visible workflow. |
| `E2E-14` | Unexpected login disconnect | Authenticated login connection | Close socket; remove connection and login session exactly once; allow reconnect. | The host-level login test closes the first client, observes zero sessions/connections, then reconnects successfully. Existing `AuthenticationTests` also tests disconnect cleanup directly. | `VERIFIED` | World-player save/despawn on disconnect is not connected or verified. |
| `E2E-15` | Graceful host shutdown with active login | Composed host and authenticated loopback client | Stop accepting, close the connection, clear session, and stop host services. | Host-level login test calls `host.StopAsync()` with an active session and observes zero sessions/connections. No active world player or Mongo write is exercised. | `VERIFIED` | Active-player save, database drain and deadline behavior require an integrated player/persistence workflow. |
| `E2E-16` | Multi-client duplicate login/reconnect | Two loopback clients, same test account | Reject second active login; after first disconnect, allow a new login. | Host-level login integration test exercises duplicate response, connection close, session cleanup, and reconnect. | `VERIFIED` | Multi-player zone visibility, chat, combat and concurrent persistence are not tested. |
| `E2E-17` | Database unavailable at startup | Mongo enabled with a closed local port and short timeout | Fail startup, report unhealthy database, and avoid accepting clients. | `FoundationHostTests.UnreachableMongoDatabaseFailsStartupAndIsNotReportedHealthy` verifies startup failure and unhealthy health result. The host test does not bind listeners because persistence starts first. | `VERIFIED` | Database loss after startup/gameplay and reconnection behavior are not tested. |
| `E2E-18` | Database failure during gameplay | Live database plus active persisted gameplay | Surface failure without corrupting player/world state, then recover where supported. | Not executed; there is no integrated persisted gameplay workflow or live Mongo test in this run. | `BLOCKED` | Requires an isolated Mongo instance, implemented gameplay persistence, and recovery contract. |
| `E2E-19` | Partial network startup rollback | Login port available; world port intentionally occupied | Fail startup and release the login listener already opened. | `NetworkAuthenticationHostIntegrationTests.WorldListenerBindFailureReleasesLoginListenerDuringStartupRollback` passes; the login port can be rebound after failure. | `VERIFIED` | Listener runtime failure after successful startup is not injected/monitored end-to-end. |

